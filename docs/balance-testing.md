# バランステスト

Milestone 9では、同一シナリオと同一シード系列を使い、4つの基準戦略を30日間運営して比較する。

## 実行方法

```bash
npm run balance
```

標準ではシード1〜100を実行し、次のファイルを生成する。

- `artifacts/balance/balance-benchmark.json`
- `artifacts/balance/balance-benchmark.csv`

CIでも100シードを実行し、Milestone合格条件を満たさない場合は失敗させる。

```bash
npm run balance:ci
```

直接CLIを呼ぶ場合は、シード範囲や出力形式を変更できる。

```bash
npm run build:core
node dist-core/balance/runBenchmark.js --seed-start=101 --seeds=100 --format=both
```

利用可能な引数：

- `--seed-start=1`
- `--seeds=100`
- `--format=summary|json|csv|both`
- `--out=artifacts/balance/custom-name`
- `--strategies=short_low_cost,long_hours`
- `--strict`：Milestone合格条件を満たさない場合、終了コード2を返す

## 基準戦略

### 短時間・低コスト型

- 8〜20時営業
- 人員を絞る
- 売り切り重視
- 一日一回納品
- 行列が深刻な場合だけ昼人員を追加する

### 長時間営業型

- 6〜24時営業
- 欠品防止発注
- 全カテゴリ二回納品
- 夜間負荷が高い場合は夜人員を追加する

### 昼食特化型

- 即食食品の売場を拡張
- 昼人員を最大化
- 即食食品を二回納品
- 欠品が続く場合は全カテゴリ二回納品へ切り替える

### 地域総合型

- 7〜23時営業
- 品ぞろえを均衡させる
- 行列、棚欠品、平常時で作業優先を切り替える
- 地域習慣と安定運営を重視する

## KPI

### 30日利益

30日間の日次利益合計。融資などの資金移動は含めない。

### サービス信頼度

現時点では独立した店舗信頼値がないため、次を抑えた割合を代理指標として使う。

- 行列離脱
- 商品在庫欠品
- バックヤード在庫がある状態での棚欠品

### 生活習慣

30日目の4習慣の地域定着度平均と、自社寄与度平均を分けて記録する。

### 安定性

次を合成した0〜1の指標。

- サービス信頼度
- 資金生存率
- 作業積み残し
- 廃棄効率

### 競争対応

最終7日間の自社・競合間の来店シェアを使う。競合AIの行動回数も別項目で記録する。

## 無操作シナリオの進行確認

30日シナリオは、同時に複数の問題が起きていても、プレイヤーへは次の順で一つずつ提示する。

1. 1日目：朝の営業時間外流出
2. 2日目：昼食商品の供給不足
3. 3日目：欠品対策後の廃棄
4. 4日目：閉店後需要

診断では「提示日」と、その提示を裏付ける「実績発生日」を分けて記録する。各チェックポイントまでに数値上の根拠が存在する場合だけ、その問題を提示可能と判定する。これにより、固定文言だけで合格させず、実際の日報に朝需要の未達、即食食品または棚の欠品、廃棄、夜需要の未達があることを確認する。

## Milestone合格判定

次をすべて満たすと合格になる。

1. 4戦略中3戦略以上が、60％以上のシードで実用判定を得る
2. 一つの戦略が利益・信頼・習慣・安定性・競争対応の全指標で首位にならない
3. 無操作プレイで、朝流出、昼欠品、廃棄、閉店後需要を順番に提示できる実績根拠が、60％以上のシードで各チェックポイントまでに存在する

合格しない場合も通常実行では結果を出力する。CIと`--strict`実行では不合格を終了コード2として扱い、調整不足を見逃さない。
