## 1. プロジェクトの目的

初代『ザ・コンビニ』を想起させる、一店舗の営業を眺めながら経営判断を行うスマートフォン向けコンビニ経営ゲームを開発する。

単なる管理画面ではなく、以下が画面内で連続して見えるゲームを目指す。

- 客が入店する
- 商品棚まで歩く
- 商品を手に取る
- 別の商品を探す
- レジへ並ぶ
- 店員が会計する
- 店員がバックヤードから補充する
- 品切れ、行列、清掃不足などが店内の見た目へ直接現れる

街マップ、複数店舗、シナリオは後回し。まずは一店舗のフリープレイを成立させ、その箱庭の中で遊びを見極める。

---

## 2. ユーザーが求めている方向性

### ゲーム構造

- 最初にシナリオを作り込まない
- 一店舗のフリープレイを先に完成させる
- 売場、商品、発注、人員、営業時間が互いに影響する
- 店内を眺めているだけでも営業状況が分かる
- 配置変更が客動線、補充距離、行列、売上へ反映される
- 後からマンネリ防止や難易度調整としてシナリオを追加する

### ビジュアル

参考イメージは初代『ザ・コンビニ』系の店内一望画面。

重要な要素：

- 店内が画面の主役
- 棚、商品、店員、客が十分な大きさで見える
- 商品が並んでいる密度感
- 店内の賑わい
- 品切れや行列がその場で分かる
- 上部に日付、時間、天気、所持金など
- 下部にタッチしやすい管理メニュー
- コンシューマ機のボタン表記やFキー表記は使わない
- スマートフォン横画面前提
- UIは指で押せる大きさ
- 文字は画像へ焼き込まず、ゲーム側で高解像度描画する

避けるもの：

- 業務システム風の大きな常設サイドパネル
- 大量の空白
- 小さすぎる人物
- 単純な長方形だけの仮什器
- 数値中心で店内の出来事が見えない画面
- 「高解像度化しただけ」の仮グラフィック

## 3. 開発・運用ルール

- ユーザー本人がPRをマージする
- アシスタント側から勝手にマージしない
- 原則、ドラフトPRを作成する
- PRを作成したらURLをすぐ提示する
- APK完成時はインストール用リンクを提示する
- 実装は細切れにせず、まとまったMilestone単位で進める
- 「できた」と言う前にAPK内部まで確認する
- GitHub Actionsの緑表示だけで必要な画像が含まれると判断しない
- APKへ実際にアセットが入っているかZIP/APK内部を確認する
- AndroidデモAPKは固定署名を維持する
- 今後「MDに記録して」という指示は、そこまでの作業内容を引継ぎ用Markdownへまとめ、Gitリポジトリ内へ保存する意味として扱う

### Android固定署名対応

過去のAPKがGitHub Actionsの一時ランナーごとに別のdebug.keystoreで署名され、旧版を残したまま新APKを上書きできなかった。

修正内容：

- デモ専用の固定署名鍵
- Gradleへ署名情報を明示注入
- APK証明書SHA-256を検証
- GitHub Actionsのrun numberをversionCodeへ使用

固定証明書SHA-256：

`A4:45:79:07:F3:4E:3B:62:81:30:5F:B4:11:E0:A5:63:5F:CE:5B:4A:05:66:27:0B:A1:B3:24:0E:64:D5:11:BF`

関連PR：

- PR #31 `Fix: AndroidデモAPKの署名を固定`

固定署名導入前のAPKから移行する初回だけ旧版アンインストールが必要。以後は上書き更新で保存データを維持できる。

### Milestone 15

文字潰れ対策と高DPI描画を実装。

- 論理座標と内部描画解像度を分離

- 人物が極小
- 店内が空白だらけ
- 右側の管理パネルが大きい
- モック相当の完成度になっていない

## 6. 現在判明している重大な問題

### 実画像WebPがmainに存在しない

本来必要なファイル：

- `public/assets/store/fixtures.webp`
- `public/assets/store/staff.webp`
- `public/assets/store/customers.webp`
- `public/assets/store/icons.webp`

現在のmainで`fixtures.webp`を確認したところ404。正式パスへ実画像が入っていない。

### PR #35の変更一覧にもWebPが含まれていない

PR #35に含まれているのは主に：

- `.m16direct/chunk.*`
- `.m16/source.*`
- `.m16asset/*`
- `.m16r/*`
- 一時的な組み立てワークフロー
- 描画プログラム
- CSS
- テスト
- ドキュメント

肝心のWebP4枚は変更ファイル一覧に存在しない。

### 成功した通常APKにも実画像が入っていない

成功したAndroid Demo APKは、通常のWebビルドと固定署名には成功している。

しかし、実画像がなくてもフォールバック描画で動作するため、APK自体は成功してしまう。

確認結果：

- 成功APKは実行可能
- 最新コードは入っている
- `assets/store/*.webp`は入っていない
- 「実画像店内版APK」ではない

以前の「実画像4アトラスを組み込み済み」「実画像素材を検証済み」「実画像店内版APKが完成」という説明は誤り。

- `.github/workflows/assemble-m16.yml`

- `.m16asset/`

- `.m16/source.00`
- `.m16/source.01x`

- `.m16direct/COMPLETE`

- `.m16r/asset.02_03`

次の修正PRで削除する。

## 10. 実画像素材について

過去のチャットで以下の素材シートを画像生成した。

- UIパーツ
- 什器・環境
- 店員
- 客

方向性についてユーザーは「いいじゃん」と評価。

失敗原因は、これらをゲームへ取り込む際に実画像を直接使わず、簡易SVGへ置き換えたこと。

次回は：

- 生成画像を実ファイルとして確保
- 背景透過
- セル位置を明示
- スプライトアトラス化
- 正式WebPまたはPNGとしてコミット
- コード側のセル寸法と一致
- 実画像そのもののSHAを固定

生成素材の元画像を次チャットで参照できない場合は、同じ方針で再生成する。

## 14. 現時点の結論

ゲームシステム側は、一店舗の営業、個体客、店員、在庫、行列、補充、清掃、売場編集まで進んでいる。

現在の最大課題はゲームロジックではなく、モック相当の実画像を本当にAPKへ組み込む工程の確立。

Milestone 16は「コードはmainへ入ったが、実画像アセットの正式コミットとAPK封入に失敗した状態」。

次回は新機能を増やさず、まずこの状態を整理し、実画像が確実に入ったAPKを完成させる。
