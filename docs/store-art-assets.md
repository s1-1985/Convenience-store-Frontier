# 店内営業画面のゲーム素材

店内営業Canvas(`storeGameRuntime.ts`)は2Dドット絵(ハードエッジ・ピクセルアート)のPNGアトラスを描画する。什器の視点は「正面・わずかに見下ろし」で統一し、側面パネルが見える斜め視点にはしない。

## アトラス

| ファイル | 内容 | セル構成 |
|---|---|---|
| `fixtures.png` | 店内什器12種(entrance/drinks/dessert/ready_meal/magazines/register/snacks/instant/daily_goods/waste/backroom/empty) | 4列×3行、384×256px/セル |
| `fixture-bases.png` | 空の什器本体2種(常温ゴンドラ/冷蔵ケース) | 2列×1行、384×256px/セル |
| `merchandise.png` | 商品オーバーレイ7種(drinks/dessert/ready_meal/magazines/snacks/instant/daily_goods) | 7列×1行、384×256px/セル |
| `staff.png` | レジ・補充・清掃の店員、前後左右 | 4列×3行、192×256px/セル |
| `customers.png` | 客36種、前後左右×3コマ | 12列(4方向×3コマ)×36行、160×220px/セル |
| `icons.png` | 時刻・カレンダー・客数・在庫箱・売上グラフ・硬貨(売上)・財布(所持金)・天気 | 8列×1行、128×128px/セル |

`icons.svg` は下部ナビゲーション(店舗/商品/発注/人員/情報)のCSS背景画像として別途使われており、`icons.png`とは無関係の別アセット。

`fixtures.png`のうちdrinks/dessert/ready_meal/magazines/snacks/instant/daily_goods/emptyの8セルは、
下記の什器レイヤー方式の導入後は`drawFixtureArtwork`から参照されない(常温什器・冷蔵ケースはカテゴリーを
持つ限り常にレイヤー方式で描画されるため)。entrance/register/waste/backroomの4セルのみ現役。未使用セルは
削除しても実害はないが、当面はそのまま残置している。

## 什器と商品の組み替え

商品入りの棚を一枚絵として固定せず、`fixture-bases.png`（空の什器）と
`merchandise.png`（商品陳列)を同一サイズのセルとして重ねて描画する。
通常ゴンドラと冷蔵ケースのどちらに商品を載せられるかは
`fixtures-manifest.json`で宣言し、Claude Codeを含む実装担当は画像の座標を
推測せず、このマニフェストを参照する。`merchandise.png`の各セルは在庫量に応じた
横方向クロップ(`fillRatio`)にそのまま使われるため、他アトラスのように内容へ
トリミングせず、セル全体(384×256px)へ均等に配置してある。

商品の表示量はシミュレーション上の棚在庫率から`full`、`normal`、`low`、
`empty`の4状態へ変換する。商品レイヤーだけを横方向に減らすため、在庫が
なくなっても空の什器はその場に残る。カテゴリを変更するときも什器画像を
作り直す必要はなく、商品レイヤーのセルを差し替える。

## 客層のバリエーション

`customers.png`は未就学児から高齢者までの年齢層(男女)に加え、不良・無職・
トラックドライバー・土方・ブルーカラー等の職業/属性アーキタイプ(行0-23)、
ChatGPT製アセットパックから採用した店舗制服風の客(行24-31、元は店員用素材)、
および同じくChatGPT製の歩行スプライトシートから採用した私服の若年客4種
(行32-35、2026-09-03追加)を含む36種を収録する。各行が1アーキタイプ、列は
前後左右×歩行コマ(`facingColumns`・`framesPerDirection`)。行とアーキタイプの
対応は`customers-manifest.json`を参照する(座標を推測しないこと)。

行0-23の客アーキタイプについては、`data/cohorts/customer_cohorts.json`の6コホートに
対応するもの(`storeGameRuntime.ts`の`COHORT_ARCHETYPE_ROWS`参照)は人口×時間帯活動率に
基づく重み付き出現、それ以外は一律の少量フレーバー枠として出現する
(`UNMODELED_ARCHETYPE_WEIGHT_SHARE`)。行24-35(店舗制服風4種・私服若年客4種)は、
まだどのコホートにも割り当てていないため、この一律フレーバー枠からのみ出現する。

行32-35は現時点で唯一、実際の複数コマ歩行差分アートを持つ行である。他の全行
(0-31)は同じ12列レイアウトへ拡張されたが、元の単一コマを3コマぶん複製しているだけ
なので見た目は静止のまま(移行前と完全に同一)。`CUSTOMER_FRAMES_PER_DIRECTION`
(`src/ui/storeArtAssets.ts`)を3に上げたことで、行32-35のみアニメーションして見える。
右向き(`right`)は元素材に無いため、左向き(`left`)の3コマを水平反転して充当している。
2体(私服女性2種)は元素材が2コマしか無かったため、[A,B,A]の順で3コマ目に1コマ目を
再利用して埋めている。

## 文字の扱い

画像内の文字はゲーム表示に使用しない。商品カテゴリ名、日付、時刻、売上、警告、ボタン名はゲーム側で日本語フォントとして描画する。これにより端末解像度や表示倍率が変わっても文字を読める状態に保つ。

## 描画解像度

ゲーム座標は従来どおり1080×500を維持する。Canvasの内部バッファだけを端末の`devicePixelRatio`に合わせ、最大3倍まで高解像度化する。画面比率を維持して中央へ配置し、営業画面と売場編集オーバーレイを同じ解像度へそろえる。CSS上の表示寸法は整数ピクセルへ丸め、サブピクセル配置による輪郭のぼやけを防ぐ。

## フォールバック

素材の読み込みに失敗した場合は、既存の矩形による仮描画へ戻す。素材障害によって営業シミュレーション自体が停止しない構成とする。

## 未統合の素材原本

ゲームへ統合済みの上記アトラス以外に、ChatGPT側が採用判定した什器・商品
モジュール・キャラクターのスプライトシート原本を`art-source/chatgpt-adopted-v1/`
配下にgit管理している(2026-09-02追加)。`data/`と異なりビルド成果物には
含まれない。個体切り出し・統合の進め方は`art-source/README.md`を参照。

## 実機確認

Android横画面で、上部の時刻・所持金、棚の商品名、在庫警告、右側の営業数値、下部メニューが拡大表示でも判読できることを確認する。売場編集時は営業Canvasと編集Canvasの位置およびタップ座標が一致していることも確認対象とする。
