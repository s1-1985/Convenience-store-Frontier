# AndroidデモAPKの固定署名

## 問題

GitHub Actionsの一時ランナーでAndroidプロジェクトを毎回作り直すと、既定の`~/.android/debug.keystore`も毎回新しく生成される。

Androidは、同じapplicationIdのアプリを別の署名鍵で上書きできない。そのため旧デモ版が端末に残っていると、新しいAPKのインストールが「アプリはインストールされていません」で失敗していた。

## 対応

- デモ専用の固定デバッグ鍵をリポジトリへ保持する
- ビルド前に固定鍵を`~/.android/debug.keystore`へ復元する
- 鍵ファイルと完成APKの証明書SHA-256をCIで照合する
- GitHub Actionsのrun numberをAndroidの`versionCode`へ設定する

固定証明書SHA-256：

`A4:45:79:07:F3:4E:3B:62:81:30:5F:B4:11:E0:A5:63:5F:CE:5B:4A:05:66:27:0B:A1:B3:24:0E:64:D5:11:BF`

## 移行

固定署名導入前のAPKとは署名が異なるため、固定署名版を最初に入れる時だけ旧版のアンインストールが必要になる。

固定署名版を一度インストールした後は、以降のデモAPKを上書き更新でき、アプリ内保存データも維持できる。

この鍵は開発中の端末配布用デモにのみ使用し、Google Play公開用の本番署名鍵としては使用しない。
