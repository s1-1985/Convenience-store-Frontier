# ADR-0011: ライバル経営AIの閉店判断(§8.1)の移植と、runToEnd()の潜在バグ修正

Status: Accepted
Date: 2026-10-09

## Context

ユーザーから「MDで解析されてないものは取り掛からなくていい」との指示があり、
これを「数式自体が判明している部分は、エンジニアリング上の規模に関わらず実装
してよい」と解釈した(ADR-0010の延長)。ライバル経営AI(design/ps1-reference/
algorithms.md §8.1、閉店判断)の判定式自体(連続赤字月数>=6で閉店)は完全に
判明しているため、着手した。

### 入力データの欠落とその補い方

§8.1は「競合店舗の月次損益」を必要とするが、本プロジェクトは競合店舗の商品別
売上・在庫・補充をシミュレートしていない(来店数の公開情報のみ)。これはMDに
解析結果が無いのではなく、本プロジェクトの既存アーキテクチャが競合店舗の内部を
数値として持っていないことによる。

プレイヤー店舗の実績(1来店あたり売上・原価率)を競合店舗の来店数に適用する
独自設計で近似した。人件費・光熱費は、既存のfinance.tsと同じ式を競合店舗自身の
`staffingByTimeBlock`・営業時間に対して使う(これらのフィールドは競合店舗にも
元から存在する)。

保護条件(「初出店直後」「自社9店舗展開時の特殊条件」)は、本プロジェクトが
複数店舗展開(2号店)を`docs/backlog.md`の試作中禁止事項としているため、該当する
状況が発生しない。実装はしていない(除外ではなく、前提条件が成立しないため)。

### 実装中に発見した既存の潜在バグ

閉店処理は、該当店舗の`openingHour`を`closingHour`と同じ値にし、
`evaluateStore()`の`isWithinHours()`判定を常にfalseにすることで表現した
(配列から店舗を削除する仕組みが無いため)。

これを`CompetitiveSimulation.runToEnd()`経由でテストしたところ、閉店判断自体は
正しく記録されるのに、実際の客の店舗選択には反映されない、という不整合が
見つかった。原因は`runToEnd()`の実装:

```ts
runToEnd(): void {
  core.runToEnd();       // 全日程を一括処理
  syncCompletedDays();   // その後に1回だけ競合AIの行動を同期
},
```

`core.runToEnd()`が全日程を一括処理してから`syncCompletedDays()`(競合AIの
行動・本ADRの閉店処理を適用する場所)を**1回だけ**呼んでいたため、競合店舗への
行動(既存の価格変更・営業時間変更・今回追加した閉店処理すべて)が、シミュレー
ション中の実際の客選択には一切反映されていなかった。`advanceDay()`を外から
ループで呼ぶ場合は正しく機能するため、これは今回のADR-0010/0011の作業で初めて
見つかった既存コードの潜在バグであり、新規に導入したものではない。

影響範囲を調査した結果:
- `src/balance/benchmark.ts`の`runBalanceStrategy()`(4戦略比較の本体)は
  `advanceDay()`ループを使っており、影響を受けていなかった
- `diagnoseNoActionRun()`は`runToEnd()`を使っており、競合AIの行動が反映され
  ないまま「無操作時の診断」を行っていた(影響範囲はこの1箇所)

## Decision

1. `src/simulation/rivalAi.ts`に§8.1の閉店判断を実装する。入力は上記の独自設計
   近似値を使う。
2. `CompetitiveSimulation.runToEnd()`を、`core.advanceDay()`を`core.isFinished()`
   まで外側からループし、毎日`syncCompletedDays()`を呼ぶ実装へ修正する。
   `core`内部のRNG消費順序(`processSlot()`の呼び出し列)は変化しないため、
   既存の固定シード回帰テストへの影響は無い(確認済み)。

## Consequences

- `diagnoseNoActionRun()`の出力は、今後は競合AIの行動(既存の価格変更・営業
  時間変更を含む)が正しく反映された値になる。固定の数値しきい値を検証する
  テストは無かったため、既存テストは全て通過したが、この診断結果自体の数値は
  今回の修正前後で変わり得る(バグ修正なので、変わった方が正しい)。
- 閉店した競合店舗は、以後`openingHour`を`closingHour`に毎日再固定する
  (既存の競合AIが`close_later`等で営業時間を動かしても上書きされる)。
- 出店判断(§8.2)は、街の成長(§7)と同じタイルグリッド(立地探索)に依存する
  ため、今回は対象外とした。街の成長モジュール(`townGrowth.ts`)は既に存在
  するため、次の増分として着手しやすい状態にある。
