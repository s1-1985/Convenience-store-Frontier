# ADR-0007: 初代ザ・コンビニ(PS1版)解析データに基づく忠実再現路線

Status: Superseded by ADR-0008
Date: 2026-10-09

## Context

ユーザーが初代「ザ・コンビニ」PS1版のゲームディスクを吸い出し、実行ファイルを
別セッション(ChatGPT)で逆アセンブル・解析させている。その途中経過
(`design/ps1-reference/`参照、128,871行・約28MBの引継ぎファイル)には、需要生成・
客の購買行動・店舗評価・店員AI・財務・街の成長・ライバル経営AIなど、原作の
中核アルゴリズムの多くが、実機のMIPS命令実行と照合済みの精度で復元されている。

ユーザーから「この中には実際の初代ザ・コンビニの中で動いていたアルゴリズム等の
データがあるので、これを取り込んで。で、より忠実に初代ザ・コンビニの再現に向けて
進めて」との指示があった。

これは`design/PRINCIPLES.md`の既存記述と部分的に緊張関係にある。同ファイルは
「本作固有の面白さ」として次を挙げている。

> 史実を再現するだけでなく、別のコンビニ史を作れる

これまでの設計は、コンビニの歴史(1970年代〜)を背景として参照しつつも、
特定の1本のゲーム(初代ザ・コンビニ)の内部挙動を忠実再現することを目的とは
していなかった。

## Decision

ユーザーの指示を、以下の優先順位の変更として受け入れる。

1. **PS1版解析データは、本プロジェクトのバランス数値・アルゴリズムの一次参考
   資料として扱う。** `design/ps1-reference/algorithms.md`に抽出済みの数式を
   集約した。独自のバランス調整が必要な箇所(本プロジェクト独自のカテゴリ
   構成・街モデル等、原作と1:1対応しない部分)では、PS1解析データを「参考に
   しつつ本プロジェクトの文脈で再設計する」が、入手可能な原作の数式がある
   箇所は、特段の理由がない限りそれを優先して移植する。
2. **`design/PRINCIPLES.md`の「史実を再現するだけでなく、別のコンビニ史を
   作れる」は撤回しない。** この原則は「プレイヤーの選択によって歴史が分岐
   しうる」という自由度の話であり、「個々のシステムの計算式が原作と異なる
   べき」という意味ではないと解釈する。PS1版のアルゴリズムを土台にしても、
   プレイヤーの経営判断による分岐(競合の反応、文化の普及、街の成長)という
   本プロジェクトの核は維持される。
3. 移植は一括では行わない。PS1解析データは本プロジェクトの`src/simulation/*.ts`
   (約2,600行、タイル単位の街・144客プロファイル・設備単位のレイアウトなどを
   持たない抽象モデル)よりはるかに詳細な粒度を持つため、1システムずつ、
   ユーザーに優先順位を確認しながら移植する。

## Consequences

- 以後の需要・店舗評価・店員AI・財務・街・競合AIの数値設計は、独自に決める前に
  `design/ps1-reference/algorithms.md`を確認し、対応する原作アルゴリズムの
  有無を調べることを標準の手順とする。
- 乱数生成式を原作のLCGへ置き換えるなど、既存の回帰テスト基準値
  (`src/tests/*.test.ts`の固定シード比較、`npm run balance:ci`)に影響する
  変更は、着手前に必ずユーザーへ確認する(`CLAUDE.md`の「基盤的な設計判断は
  ユーザーへ確認する」運用に従う)。
- PS1解析データの引継ぎファイル自体はこのセッション限りの一時アップロードで
  あり、次セッションには残らない。読み取れた範囲は`design/ps1-reference/`へ
  保存済みだが、未読範囲(商品発注・在庫管理の全体、事件発生、採用・退職等)が
  必要になった場合は、ユーザーに再アップロードを依頼する。
- 原作の忠実再現を志向することで、`docs/vertical-slice.md`・`docs/game-design.md`
  の既存の数値設計(商品カテゴリ構成、顧客コホート区分等)と、PS1解析から
  読み取れる原作の区分(144客プロファイル、27商品、53設備種別)との間に
  ギャップが生じる。このギャップをどう埋めるか(本プロジェクトの区分を原作に
  寄せて再設計するか、現行区分を維持して数式だけ移植するか)は、システムごとに
  個別のADRまたはユーザー確認を要する。
