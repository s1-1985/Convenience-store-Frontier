# 初代ザ・コンビニ(PS1版)解析データ — 参照資料

## これは何か

ユーザーがPS1版「ザ・コンビニ」のゲームディスクから実行ファイル(`SLPS_007.82`)と
マップファイルを抽出し、ChatGPT(別セッション)に逆アセンブル・解析させている
途中経過のアップロードファイル(`Conveni-PS1-Claude-Handoff.md`、128,871行・約28MB、
2026-10-09時点)から、Claude Codeが読み取れた範囲を整理したものである。

**アップロードファイル自体は次セッションに持ち越されない**(セッション限定の
一時ファイル)ため、読み取れた内容のうち再利用価値が高いものをこの参照資料として
リポジトリに保存した。元ファイルが必要な場合はユーザーに再アップロードを依頼する
こと。

## 解析データの性質(元ファイルの記述による)

- 対象はユーザー提供ディスクの`SLPS_007.82`(SHA256
  `d6a167a1c9e0fe98d7e44e12968caa489ac3eb7ed3b9e46012a188af8432b1fd`)と
  `TOWN0001/0002/0003/TOWNPS.BIN`。
- 手法はUnicornエンジンによるMIPS命令の実機行実行と、独立実装したPython関数の
  出力を比較する検証(「条件数」=比較した入力パターン数であり、網羅率や
  アルゴリズム数そのものではないと元ファイルが繰り返し明記している)。
- **未完成の解析途中データである。** 元ファイル冒頭にも「全解析完了を意味しない」
  「総分母が未確定なので『全体の何%』という数値は作らない」と明記されている。
- 各値の**画面表示名との対応の多くは未確定**(解析者による仮称)。例えば
  「security」という変数名は実際には店舗要約+0x0C/+0xA4のSERVICE相当を指す、
  といった仮称の付け違いの訂正履歴も元ファイル内にある。この資料でも、
  画面表示名が未確定の値には「(画面表示名未確定)」と注記する。
- 条件式・乱数消費順序は検証済みだが、**実機でのゲーム全体を通した動作再現
  (GPU・音声・CD-ROM込みの完全起動)ではない**。

## この資料の使い方

- 下記`algorithms.md`に、当面の本プロジェクトのシミュレーション層
  (`src/simulation/*.ts`)に関連度が高いと判断した部分を抽出・整理した。
  **元の逆アセンブル・検証コードそのものはこの資料に含めていない**(分量が
  膨大なため)。必要なら再アップロードを依頼し、該当セクションを再度読むこと。
- 各項目には元ファイル内の関数アドレス(例: `0x8002619C`)を残した。将来
  ユーザーが元ファイルを再アップロードした際、この参照資料をもとに該当箇所を
  検索し直せるようにするため。
- **この資料に書かれている内容は、初代ザ・コンビニが実際にどう動作していたかの
  事実として扱う。これを実装することが「初代ザ・コンビニの再現」の定義である**
  (`design/DECISIONS/ADR-0008-faithful-ps1-reproduction.md`・
  `ADR-0009-ps1-data-as-normative-truth.md`参照)。既存のdocs記述と矛盾する場合は
  この資料を優先し、既存記述側を改訂対象として扱う。本プロジェクト独自の数値で
  上書きするのは、対応する原作データが存在しない場合に限り、その理由をADRまたは
  コードコメントに明記すること。この場合、基盤的な設計判断の確認(CLAUDE.md)は
  不要(対応データがない場合・回帰テストに影響する場合のみユーザーに確認する)。

## 読み取れた範囲(2026-10-09時点)

元ファイル全体(128,871行)のうち、以下の範囲を重点的に読んだ。これ以外にも
`.asm`形式の生の逆アセンブル区間(325個のラベル)が大量にあるが、プレーンな
日本語解説・Python復元式を伴わない生アセンブリは今回読んでいない。

- 需要生成・客の来店店舗選択(`0x8002619C`〜`0x80027328`)
- 客の商品選択・季節判定・数量集約・滞在期限(`0x800319AC`〜`0x80034F50`)
- 経路探索・歩行・設備の利用面(`0x8002E138`〜`0x80030A34`、`0x80036160`〜`0x80036ABC`)
- 接客・レジ精算・待機終了(`0x8003839C`、`0x80035128`、`0x80035D58`)
- 店員の仕事選択・補充・清掃・休憩・疲労(`0x80036AC0`、`0x800371E0`〜`0x80039618`)
- 店舗評価(総合評価・5項目評価)の計算式(`0x8002287C`〜`0x8003FE84`)
- 会計の3段階帳簿・月次締めの8倍補正(`0x8001CA7C`、`0x8001CCC0`、日次/月次/年次締め)
- 街の建物成長・近隣影響・建替え(`0x8002BD54`、`0x8002C1B8`〜`0x8002CF7C`)
- ライバル経営AI(月次の出店・閉店判断)(`0x8002A8E0`)
- 乱数生成式(`0x8007E648`)、時刻変換(`0x80019EB4`)
- 店舗有効リストの並べ替え(`0x8001BD78`)

**2026-10-09追補**: 上記の重点範囲以外に、元ファイルには実データを含む埋め込み
JSON(`## <ファイル名>.json`形式の見出しの下に収録)が多数ある。以下は、街の成長・
ライバル経営AI・需要生成の移植作業中に見つけ、`algorithms.md`へ反映した。

- `demand-tables.json`: 月別天候抽選の12ヶ月分の閾値表、商品0〜26番の季節区分
  配列、客グループ(街タイル→客プロファイル割当)、週間カレンダー、営業時間
  スケジュール3種を実データとして収録
- `town-building-tables.json`: 街の建物カテゴリ表(72種類、id/レベル範囲/
  category0〜10/日本語名称)を実データとして収録。`src/simulation/townGrowth.ts`の
  `TownTileCategory`はこの表に基づいて修正済み(ADR-0012)
- `layout-tables.json`: ライバル出店時のレイアウト表(30種類、3段階のサイズ)を
  実データとして収録。什器配置そのもの(raw_hex)は今回未解読
- 建物種別→人口加算値の対応表(`0x8009FF1C`、137グループ×5組)は、読み取り
  アルゴリズムの記述はあるが、実機バイナリから抽出するコードのみで実際の値は
  元ファイルに収録されていない(次の候補)

残っている未読範囲(次にユーザーが元ファイルを再アップロードした際の候補):
商品発注・在庫の全体管理、火災・強盗等の事件発生、採用・退職・給与、
セーブ/ロードの詳細、UIメニュー遷移の細部(今回大半は目を通したが接続範囲の
網羅ではない)。
